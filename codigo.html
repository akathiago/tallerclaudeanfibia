Código

HTML, CSS y JavaScript explicados desde cero. No para que los escribas: para que puedas leer lo que hizo el agente y pedirle el cambio exacto.

¿Para qué mirar esto si el agente lo escribe?

Porque en algún momento vas a querer mover una cosa dos centímetros y no vas a saber si eso se pide "en el HTML" o "en el CSS". Saber cuál de los tres archivos manda sobre qué te ahorra la mitad de las vueltas.

Y porque cuando algo se rompe, poder abrir el archivo y reconocer qué estás mirando es la diferencia entre arreglarlo y volver a empezar de cero.

Con entender esta página alcanza. No hay que memorizar nada.

Los tres, en una línea cada uno

HTML

Qué hay

El contenido y su orden: los títulos, los párrafos, las fotos, los links. Si borrás el resto, esto sigue siendo una página legible.

CSS

Cómo se ve

Los colores, las tipografías, los tamaños y —sobre todo— dónde se ubica cada cosa. No es solo pintura: el acomodo también es CSS.

JS

Qué pasa

Lo que ocurre cuando alguien toca algo: se abre un menú, se filtra una lista, aparece un aviso. Sin JS la página se ve y se lee, pero no reacciona.

La analogía de siempre, y su límite

Vas a escuchar mil veces que el HTML es el esqueleto, el CSS la ropa y el JS los músculos. Sirve para arrancar, pero tiene una trampa: te hace pensar que el CSS es decoración. No lo es. Que algo esté a la izquierda o abajo, que se acomode en el celular, que haya tres columnas o una: todo eso es CSS.

Si pedís "mové esto al costado" y pensás que es HTML, vas a buscar en el archivo equivocado.

HTML · qué hay

Todo son etiquetas

El HTML es texto común envuelto en etiquetas, que le dicen al navegador qué es cada pedazo. Una etiqueta abre, envuelve el contenido, y cierra.

<a href="notas/butaca.html">Leer la nota</a>

a
el nombre de la etiqueta — en este caso, un link
href="..."
un atributo: información extra que necesita la etiqueta. Acá, a dónde lleva el link.
Leer la nota
el contenido: lo único que se ve en pantalla
</a>
el cierre. La barra es lo que lo distingue de la apertura.

El 90% de una página son seis o siete etiquetas repetidas:

  • <h1> a <h6> — títulos, del más importante al menos
  • <p> — un párrafo
  • <a> — un link
  • <img> — una imagen
  • <ul> con <li> adentro — una lista
  • <div> — una caja sin significado, solo para agrupar
  • <button> — un botón
index.html
<!-- Esto es un comentario: el navegador lo ignora -->
<h1>Butaca</h1>

<p>La sección de cine de Cimarrón.</p>

<ul>
  <li>Estrenos</li>
  <li>Entrevistas</li>
</ul>

<a href="quiz.html">Hacé el quiz</a>

Fijate que las etiquetas se anidan como cajas adentro de cajas: los <li> viven adentro del <ul>. Lo que abre primero, cierra último.

La clase: el gancho entre el HTML y el CSS

Hay un atributo que aparece por todos lados y conviene reconocer: class. No hace nada por sí solo. Es una etiqueta pegada al elemento para poder decirle al CSS "a todos los que tengan este nombre, pintalos así".

<div class="tarjeta-nota"> ... </div>

class
el nombre que le ponés vos. Puede ser cualquiera, pero se usa en minúsculas y con guiones.

Cuando le pidas un cambio al agente y quieras ser preciso, este es el dato: "cambiá el color de fondo de .tarjeta-nota" no tiene ninguna ambigüedad.

CSS · cómo se ve

Todo son reglas

El CSS es una lista de reglas. Cada regla dice a quién le aplica y qué le hace.

.tarjeta-nota { background: #c6f526; }

.tarjeta-nota
el selector: a quién le aplica. El punto adelante significa "todos los que tengan esta clase".
background
la propiedad: qué le vas a cambiar
#c6f526
el valor: a qué. Eso es un color escrito en hexadecimal.
; y { }
el punto y coma cierra cada declaración; las llaves agrupan todas las de esa regla

Las propiedades que vas a ver el 90% del tiempo:

  • color — el color del texto · background — el del fondo
  • font-family, font-size — qué tipografía y de qué tamaño
  • padding — el aire adentro · margin — el aire afuera
  • border — el contorno
  • display: flex / display: grid — cómo se acomodan los hijos: en fila o en grilla
estilos.css
/* Esto es un comentario en CSS */

h1 {
  font-size: 48px;
  color: #0d0d0d;
}

.tarjeta-nota {
  background: #e8e0cc;
  border: 2px solid #0d0d0d;
  padding: 20px;
}

/* Solo cuando el mouse está encima */
.tarjeta-nota:hover {
  background: #c6f526;
}

Tres tipos de selector y alcanza: h1 apunta a la etiqueta, .clase con punto a una clase, #id con numeral a un elemento único.

JavaScript · qué pasa

Agarrar algo y hacerle algo

Casi todo el JavaScript de una página chica hace lo mismo: agarra un elemento del HTML, espera a que pase algo, y cambia otra cosa.

script.js
// 1 · agarrar los elementos y guardarlos con un nombre
const boton = document.querySelector('#suscribirme');
const mensaje = document.querySelector('#aviso');

// 2 · esperar a que alguien haga click en el botón
boton.addEventListener('click', function () {

  // 3 · cambiar el texto del otro elemento
  mensaje.textContent = 'Listo, ya estás suscripta.';

});

Las cuatro palabras que aparecen ahí y conviene reconocer:

  • const — guardar algo con un nombre para no repetirlo. Es una variable.
  • querySelector('#aviso') — buscar en el HTML. Se busca igual que en CSS: # para un id, . para una clase.
  • addEventListener('click', ...) — quedarse esperando un evento. El más común es el click.
  • function () { ... } — un bloque de instrucciones con nombre, que se ejecuta cuando lo llaman. Es una función.

Si algo de la página "no anda" (un botón que no hace nada, un menú que no abre), casi siempre es JS. Si algo "se ve mal", casi siempre es CSS.

Cómo se conectan los tres

El HTML manda a buscar a los otros dos

Son tres archivos separados. El HTML es el único que el navegador abre solo: adentro tiene dos líneas que van a buscar a los otros dos.

index.html · completo
<!doctype html>
<html lang="es">
<head>
  <meta charset="utf-8">
  <title>Butaca</title>

  <!-- ACÁ va a buscar el CSS -->
  <link rel="stylesheet" href="estilos.css">
</head>

<body>
  <h1>Butaca</h1>
  <p id="aviso">Suscribite a la newsletter.</p>
  <button id="suscribirme">Suscribirme</button>

  <!-- ACÁ va a buscar el JS, al final del body -->
  <script src="script.js"></script>
</body>
</html>

Dos cosas de este archivo que valen la pena:

  • El <head> es la parte que no se ve: el título de la pestaña, el idioma, los links a los otros archivos. El <body> es todo lo que sí se ve.
  • El <script> va al final del body, no arriba. Si va arriba, el JS busca elementos que todavía no existen y no encuentra nada.

Con esos tres archivos en una carpeta ya tenés un sitio. Nada más que instalar: doble click en el HTML y se abre.

Lo mínimo que hay que retener

Cuatro reflejos

  • "Falta / sobra un texto o una sección" → es HTML.
  • "Está en el lugar equivocado, o se ve feo" → es CSS. Incluye posición, tamaño y cómo se acomoda en el celular.
  • "Lo aprieto y no pasa nada" → es JS.
  • Si no sabés cuál es → describí el síntoma, no el archivo. "El botón de suscribirme no hace nada" alcanza y sobra.

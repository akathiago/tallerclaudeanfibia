Git(hub)

Dos cosas distintas con el nombre parecido. Una vive en tu computadora, la otra en internet, y saber cuál es cuál te ahorra la mitad de los problemas.

¿Por qué el paréntesis?

Porque es literal: podés usar Git sin GitHub toda la vida. Git es un programa que corre en tu máquina y funciona perfecto sin cuenta y sin internet. GitHub es un sitio web donde podés dejar una copia de lo que Git guardó.

Al revés no funciona: sin Git no hay nada que subir. Si en algún momento te trabás con esto, casi siempre es porque los dos se confundieron en uno solo.

Uno

Qué es Git

Git guarda la historia de una carpeta. Registra cómo cambian sus archivos a lo largo del tiempo.

Cuando guardás un archivo con Ctrl+S, la versión anterior desaparece. Git hace otra cosa: saca una foto de la carpeta entera —todos los archivos, como están en ese momento— y la pone en una fila. Podés sacar todas las fotos que quieras, y podés volver a cualquiera.

A cada foto se le dice commit, y lleva un mensaje que escribís vos: «portada lista», «arreglé el menú». Esa fila de mensajes es la historia del proyecto, y se lee como un diario de lo que fuiste haciendo.

  • Registra cambios
  • Compara versiones
  • Permite trabajar en ramas
  • Recupera un estado anterior

Por eso Git es el punto de guardado que te deja dejarlo trabajar tranquilo. Un agente es rápido justamente porque puede equivocarse: actúa, mira el resultado y vuelve a intentar. Si cada intento es reversible, dejarlo probar sale barato.

Repositorio

Es el nombre técnico de «carpeta con historial», y se abrevia repo. Cuando alguien dice «subí el repo» está diciendo «subí la carpeta con toda su historia». No hay nada más.

Dos

Qué es GitHub

Un sitio web que aloja repositorios de Git. Es lo que convierte tu historial local en algo que existe fuera de tu computadora.

En tu computadora

Git

  • Guarda y compara versiones del proyecto
  • Funciona sin cuenta
  • No necesita internet
  • Si se te rompe el disco, se va con él
En internet

GitHub

  • Aloja repositorios de Git
  • Conserva una copia fuera de tu máquina
  • Te da una dirección para compartir
  • Deja que otra gente lo vea o se sume

GitHub no es el único —existen GitLab, Codeberg y varios más— pero es el más usado, y es al que Claude Code y Vercel se conectan sin que tengas que configurar nada. Por eso es el que usamos en el taller.

Tres

Un ejemplo práctico

No vas a escribir ninguno de estos comandos: se los pedís en castellano y los corre Claude. Están acá para que sepas qué está pasando cuando los veas cruzar la pantalla, y para que puedas frenarlo si no era eso lo que querías.

Lo que le decís Lo que corre por atrás
Empezá a llevar el registro de esta carpeta.
git init

Crea el historial. Se hace una sola vez por proyecto: de acá en adelante, esa carpeta es un repositorio.

Guardá esto, que ya funciona.
git add . git commit -m "portada lista"

Saca la foto. add elige qué entra y commit la guarda con tu mensaje. Este es el punto al que vas a poder volver, así que guardá seguido y cada vez que algo ande.

Mostrame qué cambió desde la última vez.
git status git diff

Qué archivos tocó y qué dice cada cambio. Antes de guardar, mirá: es la forma de no dar por bueno algo que no leíste.

Volvé a como estaba antes de que rompas el menú.
git checkout

Devuelve los archivos a una foto anterior. Lo que hiciste después no sobrevive, y eso es exactamente lo que estás pidiendo.

Subilo a mi GitHub.
git remote add origin … git push

La primera vez conecta tu carpeta con un repositorio en internet. De ahí en más, push manda las fotos nuevas y listo.

Traé lo que haya cambiado en GitHub.
git pull

El camino inverso: baja lo que esté nuevo allá. Sirve cuando trabajás desde dos computadoras, o cuando alguien más tocó el proyecto.

El comando exacto puede variar —hoy Git también tiene git switch y git restore para lo que antes hacía checkout—. No importa: lo que importa es saber qué le estás pidiendo.

Ojo con la diferencia

Claude Code tiene su propio /rewind, que rebobina el código y la conversación juntos. Es cómodo, pero vive dentro de la sesión. Git es más lento de explicar y mucho más duradero: el historial queda en la carpeta para siempre, lo lea Claude o no.

Cuatro

De tu carpeta a una dirección

Dónde encaja GitHub en el camino que hace tu proyecto hasta ser un enlace que podés mandar por WhatsApp.

  1. 01

    Funciona en tu compu

    Lo abrís en tu navegador y anda, pero solo existe en tu máquina.

    localhost
  2. 02

    Queda guardado y versionado

    Subís el repositorio. Ahora existe fuera de tu computadora, con toda su historia.

    GitHub
  3. 03

    Se publica una copia

    Un servicio mira tu repositorio y arma el sitio público a partir de él.

    Vercel · Netlify · GitHub Pages
  4. 04

    Probás el enlace final

    Abrilo vos primero, en el teléfono también, antes de mandárselo a nadie.

    la URL que compartís

Vercel se queda mirando tu repositorio: cada vez que subís algo, vuelve a publicar solo. Por eso el orden importa. Primero GitHub, después la dirección.

Cinco

Lo que no va a GitHub

Un repositorio público es público de verdad: cualquiera lo lee, los buscadores lo indexan y borrarlo después no lo saca del historial. Vale la pena pensarlo dos minutos antes del primer push, y no dos días después.

Antes de subir, sacá de la carpeta:

  • Claves y contraseñas. API keys, tokens, accesos. Van en un archivo .env, que se excluye con un .gitignore. Pedíselo a Claude: sabe hacerlo.
  • Material de fuentes. Audios, transcripciones, documentos, capturas: cualquier cosa con nombres de personas o que te hayan dado en confianza.
  • Borradores que no querés que se lean. El historial guarda todo, incluso lo que borraste después.

Si dudás, hacé el repositorio privado. Es gratis, y pasarlo a público después es un click.

Y si ya subiste una clave por error: no alcanza con borrarla y volver a subir. Dala por filtrada y cambiala.

Para llevarse

Lo mínimo que tenés que recordar

  • Git saca fotos de tu carpeta. Vive en tu máquina.
  • GitHub guarda una copia de esas fotos en internet y te da una dirección.
  • Se los pedís en castellano a Claude. Los comandos son de él, la decisión de cuándo guardar es tuya.
  • Guardá cada vez que algo funcione. Es lo que hace que romper el proyecto deje de dar miedo.
